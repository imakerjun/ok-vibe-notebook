# 바이브 코딩 노트 채우기

## 상황

사용자는 OK금융그룹 바이브 코딩 워크숍에 참가한 비개발 임직원이다. 오전에 업무 스킬 1개, 오후에 업무 웹앱 1개를 만들었다. 이 폴더는 그 내용을 사용자 본인의 사례로 정리하는 노트다.

이 노트는 **인터넷에 공개될 수 있다**. 주소를 아는 누구나 읽는다고 보고 쓴다.

페이지는 3장이다.

| 파일 | 내용 |
|---|---|
| `index.html` | 홈. 노트 한 줄 소개, 만든 것 2개, 오늘 만든 스킬 목록, 오늘 만든 아티팩트 링크, AI와 프로그램 나누기, 다음 주 할 일 |
| `skill.html` | 1부. 내 업무 스킬 |
| `webapp.html` | 2부. 내 업무 웹앱 |

채울 칸은 `class="placeholder"`이고 `data-fill` 이름이 붙어 있다. 칸 안의 `placeholder-label`이 무엇을 쓸지, `placeholder-hint`가 어떤 모양으로 쓸지다. `components.html`은 블록 견본이라 채우지 않는다.

## 순서

1. **재료부터 읽는다.** 사용자에게 묻기 전에 워크숍 폴더를 먼저 본다.
   - 기본 위치는 바탕화면의 `ok-workshop` 폴더다. 없으면 어디 있는지 한 번 묻는다.
   - 읽을 것: `ok-workshop/.claude/skills/*/SKILL.md`, `ok-workshop/업무메모.md`, `ok-workshop/index.html`(웹앱), `ok-workshop/my-site/index.html`(배포한 대시보드), 시험 입력으로 쓴 파일.
   - **읽기만 한다.** `ok-workshop` 폴더의 파일은 하나도 고치지 않는다.
   - **스킬 목록은 묻지 않고 채운다.** `ok-workshop/.claude/skills/` 아래 스킬마다 `name`과 `description`을 읽어 `home-skills` 표(스킬 이름 | 언제 쓰나 | 나오는 모양 한 줄)를 만든다. 실제 정보가 들어 있는 스킬은 이름만 남기고 설명은 일반화한다.
   - **아티팩트 링크는 목록을 보여 주고 고르게 한다.** Artifact 도구가 있으면 내 아티팩트 목록(제목, 주소, 고친 시각)을 가져와 오늘 만든 것만 표로 보여 주고, 노트에 넣을 것을 고르게 한다. 도구가 없으면 링크를 붙여 달라고 한 번 묻는다. 미션 11에서 올린 Vercel 주소가 있는지도 묻는다. 고른 것으로 `home-artifacts` 표(이름 | 무엇을 보여주나 | 링크 | 누가 열 수 있나)를 만든다.
2. **사용자가 말한 페이지만 채운다.** 페이지를 말하지 않았으면 `skill.html`부터 시작한다고 알리고 진행한다.
3. **재료에 없는 것만 묻는다.** 장면, 빗나간 곳, 느낀 점, 다음 주 할 일은 사용자만 안다.
   - 질문은 한 번에 하나만 한다. 한 페이지에 최대 3개까지 묻는다.
   - 예시 답을 함께 준다. 예: "회의록을 정리시킬 때 매번 다시 붙이던 말이 있었나요? 예: 담당자 없으면 미정으로 써"
   - 사용자가 "모르겠다", "넘어가자"라고 하면 그 칸은 빈칸으로 둔다.
4. **빈칸을 블록으로 바꾼다.** `components.html`에서 맞는 블록의 코드를 그대로 가져와 글만 바꾼다. 빈칸 `div` 전체를 지우고 그 자리에 블록을 넣는다.
   - 표지 제목처럼 `placeholder`가 아닌 요소에 붙은 `data-fill`은 안의 글만 바꾼다.
5. **공개 점검을 한다.** 아래 "공개 점검"을 돌리고 결과를 표로 보여준다.
6. **남은 빈칸을 정리한다.** 사용자가 "올릴 거야", "마무리해줘"라고 하면, 남은 빈칸마다 그 소제목과 빈칸을 함께 지울지 묻는다. 지우라고 한 것만 지운다.
7. **확인 방법을 알려준다.** 채운 파일을 기본 브라우저로 열어 준다. 실패하면 "폴더에서 파일을 더블클릭하세요"라고 안내한다.

## 하지 말 것

- **실제 정보를 넣지 않는다.** 재료에 아래가 보이면 가상 값으로 바꾼 뒤, 무엇을 바꿨는지 알린다.
  - 고객 이름·연락처·주소·계좌번호·카드번호·주민등록번호
  - 동료 실명. "B과장", "영업지원팀 A"처럼 바꾼다
  - 회사 숫자: 실적, 금액, 건수, 목표치, 연체율 같은 지표 값
  - 사내 시스템·서버 이름, 내부 주소, 비밀번호·키·토큰
  - 아직 발표되지 않은 계획이나 상품
- **사용자 이름은 묻고 쓴다.** 실명, 별명, 이름 없음 중에 고르게 한다.
- **지어내지 않는다.** 사용자가 하지 않은 일, 말하지 않은 느낌, 없던 수치를 만들지 않는다. 재료에도 없고 답도 없으면 빈칸을 그대로 둔다.
- **모양을 바꾸지 않는다.** `assets/style.css`와 `components.html`은 고치지 않는다. 새 `class`나 `style` 속성을 만들지 않는다. 쓸 수 있는 블록은 `components.html`에 있는 13개뿐이다.
- **다른 곳의 그림을 걸지 않는다.** 그림은 `images/` 폴더에 있는 파일만 쓴다. 인터넷 그림 주소를 `src`에 넣지 않는다.
- **위쪽 메뉴, 아래쪽 글, `<head>`는 건드리지 않는다.**
- **코드 블록 안의 `<`, `>`, `&`를 그대로 두지 않는다.** 각각 `&lt;`, `&gt;`, `&amp;`로 바꾼다.
- **링크를 연다고 약속하지 않는다.** claude.ai 아티팩트는 처음에 나만 볼 수 있다. 공유 범위를 바꿨는지 사용자에게 묻고, 바꾸지 않았으면 "누가 열 수 있나" 칸에 "나만 보기"라고 쓴다. Vercel 주소는 "누구나"라고 쓴다.

## 글쓰기

- 사용자 본인이 쓴 것처럼 1인칭으로, `~습니다` 체로 쓴다.
- 문장은 짧게 쓴다. 한 문장에 한 가지만 말한다.
- 숫자와 장면을 쓴다. "효율이 높아졌다" 대신 "매주 10분 걸리던 정리가 1분이 됐다"처럼 쓴다. 그 숫자는 사용자가 말한 것만 쓴다.
- "혁신", "강력한", "획기적", "여정" 같은 말은 쓰지 않는다.
- 사용자가 한 말은 되도록 그대로 살린다. 인용 블록에 넣어도 좋다.

## 공개 점검

채운 뒤 매번 아래를 돌린다. 앞의 4개는 파일을 검사해서 답이 하나로 나온다. 뒤의 3개는 읽고 판단한다.

| # | 항목 | 확인 방법 |
|---|---|---|
| 1 | 남은 빈칸 | 세 페이지에서 `class="placeholder"`가 몇 개 남았는지 센다 |
| 2 | 바깥 그림 주소 | `src="http`가 있으면 실패 |
| 3 | 새 모양 | `style="` 속성이 생겼으면 실패 |
| 4 | 코드 블록 깨짐 | `<pre><code>` 안에 바꾸지 않은 `<`가 있으면 실패 |
| 5 | 실제 정보 | "하지 말 것"의 실제 정보 목록에 걸리는 것이 있나 |
| 6 | 지어낸 내용 | 재료나 사용자 답에 없는 사실·숫자가 들어갔나 |
| 7 | 내 말 | 사용자 답에서 가져온 표현이 페이지마다 1개 이상 있나 |
| 8 | 링크 공개 범위 | 아티팩트 표의 링크마다 "누가 열 수 있나"가 적혀 있나 |

## 결과 형식

채우기가 끝나면 이 순서로 답한다.

1. 바꾼 파일과 채운 칸 이름
2. 가상 값으로 바꾼 것 (없으면 "없음")
3. 아직 빈칸인 것과, 채우려면 무엇을 알려 주면 되는지
4. 공개 점검 표. 열: 항목 | 결과(통과/실패) | 실패면 할 일

형식 밖의 긴 설명은 붙이지 않는다.

## 한 페이지로 합쳐 올리기

사용자가 "한 페이지로 합쳐 올려줘", "아티팩트로 만들어줘", "Vercel에 배포해줘"라고 하면 이 순서로 한다.

1. **합친다.** 홈, 1부, 2부 순서로 세 페이지의 `<main>` 안 내용을 이어 붙여 `publish/index.html` 한 파일을 만든다.
   - `assets/style.css`의 내용을 `<head>`의 `<style>` 안에 그대로 넣는다. 다른 파일을 읽지 않는 한 파일로 만든다.
   - 위쪽 메뉴는 페이지 안 이동(`#home`, `#skill`, `#webapp`)으로 바꾸고, 각 부분 첫 제목에 그 `id`를 붙인다.
   - 바깥 글꼴 링크(`cdn.jsdelivr.net`)는 지운다. 아티팩트에서는 막힌다.
   - `images/`의 그림은 파일 안에 넣는다(`data:` 주소). 전체가 4MB를 넘으면 그림을 줄이거나 빼자고 먼저 묻는다.
2. **점검한다.** 공개 점검 표를 다시 돌려 보여 주고, 사용자가 "올려"라고 하면 다음으로 간다.
3. **아티팩트로 올린다.** `publish/index.html`을 아티팩트로 올리고 링크를 알려 준다. 처음에는 나만 볼 수 있다고 함께 알린다.
4. **Vercel에 배포한다.** Vercel 커넥터가 있으면 `deploy_to_vercel`로 올린다.
   - `name`은 `notebook-`과 사용자 영문 이름(예: `notebook-gildong`), `target`은 `production`, `files`에는 `index.html` 하나를 내용 그대로 넣는다.
   - `get_deployment`로 READY가 될 때까지 확인하고 주소를 알려 준다. ERROR면 빌드 로그에서 원인을 한 줄로 알려 준다.
   - 커넥터가 없거나 실패하면 Vercel Drop을 안내한다: vercel.com/drop에 `publish` 폴더를 끌어다 놓고 프로젝트 이름을 넣은 뒤 Deploy.
   - 토큰이나 키는 묻지 않는다.
5. **다시 올릴 때**는 `publish/index.html`을 다시 만들고, 같은 `name`으로 배포한다. 주소는 그대로이고 내용만 바뀐다.
